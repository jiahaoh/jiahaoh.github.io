# AGENTS.md

This file provides guidance to Codex when working with code in this repository.

## Project Overview

This is Jiahao Huang's personal academic site and working-notes blog. It started
from the al-folio Jekyll theme, but the current product direction is a
blog-first, warm, CLI-flavored "plain text" site.

- Canonical domain: `https://jiahaoh.info`
- Repository/deployment target: GitHub Pages for `jiahaoh.github.io`
- Main audience: research collaborators, readers of working notes, and people
  scanning Jiahao's academic/research background

## Development Commands

### Local Development (Docker)

```bash
docker-compose up
```

The site is available at `http://localhost:8080`; live reload uses port `35729`.

### Local Development (Native Ruby)

```bash
bundle install
bundle exec jekyll serve --watch --port=8080 --livereload
```

### Production Build

```bash
JEKYLL_ENV=production bundle exec jekyll build
```

Production builds rely on ImageMagick for responsive images and `nbconvert` for
notebook support. CI installs these before building.

### CSS Purge Step

```bash
npm install -g purgecss
purgecss -c purgecss.config.js
```

### Code Formatting

```bash
npx prettier . --write
npx prettier . --check
```

## Current Architecture

### Plain-Text Site Shell

The recent redesign centers the site around a custom plain-text layout family:

- `_layouts/plain-text.liquid` is the chrome-free shell. It includes the normal
  al-folio head/scripts, then adds Lora and JetBrains Mono plus
  `_includes/plain-text-scripts.liquid`.
- `_sass/_plain-text.scss` contains the redesign styles and is imported last
  from `assets/css/main.scss` so it can override al-folio where needed.
- Plain-text pages are scoped with `body.plain-text-shell` and page-specific
  classes such as `plain-home-page` and `plain-writing-page`.
- The design source and static handoff live in `blog-redesign/`. That directory
  is a prototype/handoff artifact, not part of the Jekyll build unless it is
  explicitly wired into layouts or assets.

### Key Routes and Layouts

- `/` uses `_pages/about.md` with `layout: home`, rendered by
  `_layouts/home.liquid`. The current home screen is a hard-coded CLI prompt;
  the Markdown body in `_pages/about.md` is not rendered by this layout.
- `/blog/` is `_pages/blog.md`, a Liquid-built writing index grouped by year and
  filterable by tags/categories.
- Blog posts in `_posts/` use `_layouts/post.liquid`, which now renders with the
  plain-text shell, a fixed left metadata/TOC panel on wide screens, inline meta
  on smaller screens, and a top reading-progress bar.
- Archive pages generated by `jekyll-archives-v2` use
  `_layouts/archive.liquid`, also in the plain-text style.
- `/cv/` uses `_layouts/cv.liquid`, rendering `_data/cv.yml` into plain-text
  panels and linking `assets/pdf/CV.pdf`.
- `_layouts/page.liquid` renders generic pages in the plain-text style.
- `_layouts/default.liquid`, `_layouts/about.liquid`, `_layouts/profiles.liquid`,
  `_layouts/distill.liquid`, and `_layouts/bib.liquid` remain from al-folio for
  legacy or specialized pages.

### Client-Side Plain-Text Behavior

`_includes/plain-text-scripts.liquid` owns the small interactive layer:

- Home prompt commands currently include `blog` and `help`; `writing` aliases to
  `blog`.
- The blog index filters posts by the slugified values in `data-tags`.
- Post pages generate a TOC from `h2` elements, update active TOC state with
  `IntersectionObserver`, and drive the reading-progress bar.
- Existing copy-code behavior still comes from al-folio's shared scripts.

### Content Sources

- `_posts/` is the primary writing surface.
- `_bibliography/papers.bib` still stores publications and can be rendered by
  bibliography includes, but the old standalone publications page was removed.
- `_data/cv.yml` is the CV source used by `/cv/`.
- `_data/socials.yml` controls social metadata/icons.
- `_data/repositories.yml` and `_pages/repositories.md` are template remnants;
  the repositories page is currently `nav: false`.
- The `_projects/` collection and projects page were removed in the blog
  redesign. Do not recreate them unless the user explicitly asks.

## Styling Notes

- Global al-folio colors live in `_sass/_variables.scss` and
  `_sass/_themes.scss`. The default palette is warm beige plus rust.
- Plain-text-specific colors and typography live as CSS custom properties at the
  top of `_sass/_plain-text.scss`.
- Keep plain-text changes scoped to the plain-text shell where possible.
- `assets/css/main.scss` import order matters: `plain-text` should stay last.
- Avoid reintroducing the removed dual-persona/Dota Easter egg files unless the
  user explicitly wants to revive that experiment.

## CI/CD

Active workflows in `.github/workflows/`:

- `deploy.yml` builds and deploys `_site` on pushes to `main`/`master` and runs
  build checks on PRs. It caches npm, builds with Ruby 3.3.5 and Python 3.13,
  runs PurgeCSS, and deploys only outside pull requests.
- `prettier.yml` runs Prettier on pushes and PRs.
- `axe.yml` runs accessibility checks on pushes, PRs, and manual dispatch.
- `broken-links-site.yml` runs Lychee against the built site after a successful
  deploy workflow.

Many older al-folio workflows were intentionally removed to reduce GitHub
Actions noise and failures.

## Important Notes

- `_site/`, `.jekyll-cache/`, and `node_modules/` are generated/local artifacts.
- Source maps are excluded from production output via `_config.yml`.
- Responsive images generate AVIF and WebP variants at 480, 800, and 1400 px.
- Search is still enabled globally through al-folio's ninja-keys integration.
- The historical docs under `docs/plans/2026-01-28-dual-persona-*` are
  superseded by the plain-text blog redesign.
